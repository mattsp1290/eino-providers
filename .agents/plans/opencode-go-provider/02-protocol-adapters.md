# Protocol adapters

## WP3: Eino facade and existing adapters

Prerequisite: WP1 and WP2. All paths and symbols under proposed `opencodego/` are new, anchored to the existing repository root.

New `opencodego/adapters.go` builds the pinned Eino Chat Completions and Messages models directly. Use a fixed non-secret placeholder for SDK API-key validation; the auth transport replaces credentials. Always supply explicit model, base URL, and HTTP client, so ambient OpenAI/Anthropic credentials and endpoints cannot select another destination.

| Protocol | Wire endpoint | Cap mapping |
| --- | --- | --- |
| Chat Completions | auth `BaseURL()` + `/chat/completions` | `MaxTokens` → Eino `MaxTokens` / wire `max_tokens`; do not also send `max_completion_tokens`. |
| Messages | auth `Endpoint(ProtocolMessages)` | `MaxTokens` → Eino `MaxTokens` / wire `max_tokens`. |
| Responses | auth `Endpoint(ProtocolResponses)` | `MaxTokens` → wire `max_output_tokens`. |

Chat Completions can use the auth normalized root directly as its Eino BaseURL. Messages needs adapter-local SDK URL composition: the pinned Anthropic SDK appends `v1/messages`. For roots ending in `/v1`, pass the parent root with a trailing slash. To support arbitrary auth-valid custom root paths, use an SDK-only synthetic base rooted on the configured origin and a narrow pre-auth transport mapping of exactly that SDK Messages URL to the auth `Endpoint(ProtocolMessages)`. Reject any other SDK route rather than performing a general prefix rewrite. Do not rewrite after authentication. Cover a custom root with no `/v1`, the default root, trailing slash, and repeated path segments. Keep this mapping private to Messages and preserve method, body, context, and redirect rejection.

The facade in proposed `chatmodel.go` delegates `Generate`, `Stream`, and `WithTools` and applies backend error mapping using the operation-local state from WP2. Initial and receive errors use the same classification. New `opencodego/stream.go` forwards SDK chunks through a bounded pipe and emits normalized usage at successful EOF; it never accumulates the whole response. Its producer must close the underlying SDK reader and downstream writer on all exit paths and contain panics safely.

Usage preservation is required because the pinned OpenAI Generate converter always passes `&resp.Usage`, and Claude's Generate and message-delta converters always allocate TokenUsage. New `opencodego/observation.go` therefore wraps successful SDK response bodies with a byte-preserving observer. For nonstream responses, capture at most 16 MiB as the SDK reads, finalize JSON presence inspection on EOF/Close, and replace synthesized usage after Generate returns. Oversize or malformed observation fails the call safely. For SSE, inspect completed frames incrementally as bytes pass through, with a 10 MiB per-event cap, without waiting for later events before returning already-read bytes. Observe OpenAI top-level `usage`, Anthropic `message_start.message.usage`, and `message_delta.usage`. Do not count omitted/null usage as present. Explicit zero counters are present. Normalize the SDK's output using those wire observations, not the synthesized zero value.

For streaming SDK paths, remove SDK-generated usage from forwarded chunks and emit one final normalized usage-only assistant chunk after verified successful EOF, based on the completed wire observations. This avoids SDK read-ahead races between observation and chunk conversion. For Chat Completions use the final valid usage object's counters. For Messages retain start input/cache counters and the latest cumulative output counters from message_delta; do not sum cumulative snapshots. Missing counter families remain unavailable; a complete explicit zero input/output pair remains available. Never emit a successful final usage chunk after a receive/observer error. Preserve finish metadata and text/tool chunks independently of usage. Native Responses uses its own parser presence information and needs no duplicate observation. Add omitted/null/explicit-zero, partial counter, duplicate cumulative event, retry reset, and concurrent-operation fixtures for both SDK protocols.

SDK EOF alone is not proof of protocol completion. Track Chat Completions `[DONE]` and Messages `message_stop` in the body observer. Once the terminal frame is complete, deliver its bytes to the SDK, stop exposing any subsequent bytes, close the underlying body exactly once, and return EOF on later reads. Do not wait for the socket to close. Require the corresponding observed terminal marker before treating SDK EOF as success. Socket EOF without it is `ErrProviderAPI`, even if some text or tool fragments were emitted. Observer framing must preserve CRLF/multiline event boundaries and fail malformed/oversized frames safely. Test both protocols with premature EOF and a server that sends the terminal marker then holds the socket open. Read-ahead or buffered terminal frames must not cause an extra usage event or discard preterminal content.

Preserve operation context values through the derived observation context. A configured session is a fallback; external `opencodeauth.WithSessionID` on each Generate/Stream/Advise context overrides it. Never copy sessions between concurrent contexts. `WithTools` returns an independent model preserving config and client without modifying the receiver. Copy tool schemas into owned representation at bind time where necessary, so deriving one tool set cannot change another.

Support Eino common `WithModel`, `WithMaxTokens`, `WithTools`, and `WithToolChoice` options. Per-call model changes keep the selected protocol; validate nonempty models and positive caps after applying overrides. Tool-choice allowed/forbidden/forced maps to native auto/none/required (Messages auto/none/any through its Eino adapter). Forward existing adapter options only within their documented capability; for the new Responses model reject unsupported populated common options locally instead of silently ignoring them. Temperature, TopP, stop sequences, allowed tool names, and extra options are not promised across protocols.

Lifecycle contract: callers cancel the operation context and close the stream reader when abandoning a stream. The pinned Eino StreamReader has no public on-close hook; do not claim Close alone interrupts a blocked HTTP read. Cancellation must release a blocked read, and Close must release a blocked Send. No goroutine may require another server chunk after cancel+Close. Natural protocol completion closes the body and stream. Tests assert this under a silent server and a consumer that stops reading.

Verification: new `opencodego/chatmodel_test.go` exercises Generate and Stream through real Eino adapters and real auth transport, checks exact URL/cap/headers, runs a tool result into the next request, verifies clone isolation, per-call overrides, context session overrides, and errors on both initial and receive paths. Use `go test -race ./opencodego`.

## WP4: native Responses adapter

Prerequisite: WP3 facade contract and WP2 transport. New files under proposed `opencodego/`: `responses.go` for request/response conversion, `responses_model.go` for Eino methods and HTTP lifecycle, and `responses_stream.go` for bounded SSE framing and state. Proposed unexported `responsesModel` implements `model.ToolCallingChatModel`.

Use `openaicodex/responses.go` only as inspected Eino mapping evidence. Do not copy Codex endpoint/auth imports, mandatory reasoning defaults, error classifiers, or malformed-frame suppression. No shared parser extraction is part of this work.

Request contract:

- Generate sends native `stream:false`; Stream sends `stream:true`. Both set `store:false`, `include:["reasoning.encrypted_content"]`, explicit model, optional positive `max_output_tokens`, and selected tools/tool choice. Requesting encrypted content supports stateless reasoning replay; it does not force a reasoning effort or summary setting. Omit those optional reasoning controls by default. Do not assume IDs alone are replayable after an unstored response.
- Fold system text into `instructions`. Convert user/assistant text to native message input, assistant tool calls to `function_call`, and tool results to `function_call_output`, preserving call IDs and order.
- Serialize Eino tool parameter schemas as native function tools; validate missing names and schema conversion failures before HTTP I/O. Reject nil messages, unsupported roles, unsupported multimodal fields, missing function-call IDs, and mismatched tool-result IDs rather than dropping content.
- Preserve native reasoning items returned by the service under proposed Extra key `opencodego:reasoning_items` and replay them before that assistant turn's tool calls. Deep-copy raw JSON. Accept in-memory `[]json.RawMessage` and its normal JSON round-trip representation; reject malformed stored items. Do not log reasoning as diagnostics. Session persistence remains the host's responsibility.

Nonstream contract: bounded JSON response read (16 MiB maximum), body always closed. Decode text, all function calls, reasoning items, and usage into one assistant message. Preserve absent usage as nil. Map input/output/total and cached/reasoning detail counts to Eino fields. Tool-only completed responses succeed. Failed/incomplete responses return safe `ErrProviderAPI` errors; do not return partial success. Malformed/oversized responses fail safely. Finish reason is `tool_calls` when calls exist, otherwise `stop`.

Streaming contract:

- Parse SSE blank-line-delimited events, CRLF, comment heartbeats, and multiline `data:` joined with newline. Bound each complete event to 10 MiB, including the total of its data lines. Reject malformed recognized events and oversized frames. Ignore unknown well-formed event types for forward evolution.
- Emit text and reasoning deltas as assistant chunks. Track function calls by `output_index`, emit stable Eino ToolCall.Index and call identity, then emit arguments incrementally. Interleaved calls must concatenate into distinct valid calls. Terminal argument snapshots must not duplicate emitted fragments. A completed item without preceding deltas emits its full arguments once; inconsistent duplicate identities fail safely.
- Preserve completed reasoning items for replay. Emit usage and finish metadata exactly once at `response.completed`, validate terminal status, and stop immediately even if the socket remains open. Do not require EOF after completion. Reconcile terminal output snapshots without duplicating emitted text/calls; fail if required data is inconsistent.
- `response.failed`, `response.incomplete`, and native error events fail with safe provider errors. Do not reuse HTTP decoding on successful stream bodies. Premature EOF, malformed JSON, invalid tool state, and scanner/read failures must be errors, not successful truncation. `[DONE]` alone does not replace `response.completed`.
- Use per-request cancellation and bounded Eino pipe buffering. Defer response-body closure and writer closure in the producer. Contain panics in the adapter-owned producer with a safe error and no raw panic payload. Preserve cancellation even while blocked reading or sending. Host cancel+Close is required for early abandonment as described in WP3.

Tests in new `opencodego/responses_test.go` and `opencodego/responses_stream_test.go`: inspect native request JSON; nonstream/stream parity; text-only, tool-only and parallel tools; incremental fragments visible before completion; done-only calls; reasoning replay through concatenation and a JSON round trip; zero/missing usage; malformed/oversized frames and bodies; failed/incomplete/early EOF; terminal completion while server holds socket open; consumer cancellation; panic containment; concurrent sessions and tool clones. The reasoning fixture returns encrypted content only when the include setting is present, and rejects a second request that omits or corrupts that content. This verifies the request prerequisite as well as replay. Run `go test -race ./opencodego -run 'Responses|Session|Tools'`.

WP4 acceptance requires real HTTP fixtures using the external auth client. A parser unit test alone cannot prove credential headers, destination policy, context, or tool-loop behavior.
